# AI 输出数据格式

本文件定义分析过程中 AI 输出的结构化数据格式。所有 JSON 字段必须严格遵守，字段命名使用英文，字段值（功能名称、描述等）使用中文。

## 1. 单个功能对象

每个识别出的功能输出如下结构：

```json
{
  "功能编号": "F001",
  "功能名称": "网格数据缓存机制",
  "功能分类": "新增功能",
  "功能描述": "新增网格数据缓存能力，减少重复数据加载，并通过缓存淘汰策略控制内存使用。",
  "涉及模块": [
    "网格管理模块",
    "网格计算模块"
  ],
  "涉及文件": [
    "src/grid/GridManager.cpp",
    "src/grid/GridManager.h"
  ],
  "相关提交": [
    "abc123def456...",
    "def456abc123..."
  ],
  "代码依据": [
    "新增 CacheGridData 数据结构",
    "增加 LRU 淘汰策略实现"
  ],
  "置信度": 0.95,
  "是否需要人工确认": false
}
```

### 1.1 字段约束

| 字段 | 类型 | 约束 |
|---|---|---|
| 功能编号 | string | 分支内唯一，格式 `F` + 三位数字（如 `F001`、`F042`） |
| 功能名称 | string | 中文，简洁，不超过 30 字 |
| 功能分类 | string | 必为 8 类之一（见 `feature-taxonomy.md` §1） |
| 功能描述 | string | 中文，说明功能目的与业务价值，不超过 200 字 |
| 涉及模块 | string[] | 中文模块名，至少 1 项 |
| 涉及文件 | string[] | 相对仓库根的路径，必须是 `git diff` 实际变更的文件 |
| 相关提交 | string[] | 完整 40 位 SHA，必须真实存在 |
| 代码依据 | string[] | 中文，描述实际代码变化点，每项不超过 80 字 |
| 置信度 | number | `[0, 1]` 闭区间，越高表示识别越确定 |
| 是否需要人工确认 | boolean | `true` 表示证据不足 |

### 1.2 字段填写守则

- **功能编号** 在单个分支内从 `F001` 开始连续编号，不跨分支复用。
- **提交 SHA** 必须使用第一步固定的 40 位完整 SHA，不得使用短 SHA。
- **文件路径** 必须来自 `git diff --name-status` 实际输出，不得凭推测添加。
- **代码依据** 必须能在 `git show <SHA>` 或 `git diff` 中找到对应实现。
- 不得虚构功能；证据不足时设置 `是否需要人工确认=true` 并在描述中说明原因。
- Git 技术术语（Commit、Merge、Cherry-pick、Patch ID）保留英文。

## 2. 单个分支汇总对象

每个分支输出一份分支汇总 JSON：

```json
{
  "分支名称": "project-a",
  "基准提交": "abc123def456789012345678901234567890abcd",
  "当前提交": "def456abc123789012345678901234567890abc",
  "统计起始日期": "2026-01-01",
  "统计时区": "Asia/Shanghai",
  "功能列表": [
    { "...": "见 §1 单个功能对象" }
  ]
}
```

### 2.1 字段约束

| 字段 | 类型 | 约束 |
|---|---|---|
| 分支名称 | string | 完整 refs 路径（如 `refs/heads/project-a`）或简化名 |
| 基准提交 | string | 40 位 SHA，第一步固定值 |
| 当前提交 | string | 40 位 SHA，第一步固定值 |
| 统计起始日期 | string | `YYYY-MM-DD` |
| 统计时区 | string | IANA 时区名（如 `Asia/Shanghai`、`UTC`） |
| 功能列表 | object[] | 至少 0 项 |

## 3. 跨分支关联对象

跨分支去重阶段为每组关联功能输出：

```json
{
  "统一功能编号": "U001",
  "统一功能名称": "网格数据缓存机制",
  "统一功能分类": "新增功能",
  "统一功能描述": "新增网格数据缓存能力，减少重复数据加载。",
  "关联关系": [
    {
      "分支名称": "project-a",
      "分支功能编号": "F001",
      "关系类型": "IDENTICAL",
      "判断依据": [
        "Commit SHA 相同：abc123def456...",
        "Patch ID 相同：deadbeef..."
      ],
      "置信度": 0.99
    },
    {
      "分支名称": "project-b",
      "分支功能编号": "F003",
      "关系类型": "SAME_FEATURE",
      "判断依据": [
        "业务能力相同：均为网格缓存",
        "实现不同：project-a 用 std::unordered_map，project-b 用 LRU 专用容器"
      ],
      "置信度": 0.85
    }
  ],
  "是否需要人工确认": false
}
```

### 3.1 字段约束

| 字段 | 类型 | 约束 |
|---|---|---|
| 统一功能编号 | string | 全局唯一，格式 `U` + 三位数字 |
| 统一功能名称 | string | 中文 |
| 统一功能分类 | string | 8 类之一 |
| 统一功能描述 | string | 中文 |
| 关联关系 | object[] | 至少 1 项，每项对应一个分支 |
| 关系类型 | string | 5 类之一（见 `feature-taxonomy.md` §2） |
| 判断依据 | string[] | 中文，列出具体证据 |
| 置信度 | number | `[0, 1]` 闭区间 |
| 是否需要人工确认 | boolean | 任一关联 `UNCERTAIN` 时置 `true` |

## 4. 仓库整体汇总对象

```json
{
  "仓库路径": "/home/user/project",
  "统计起始日期": "2026-01-01",
  "统计时区": "Asia/Shanghai",
  "分析执行时间": "2026-02-01T10:30:00+08:00",
  "扫描分支数量": 8,
  "成功分析分支数量": 7,
  "失败分支": ["project-x"],
  "分支功能记录总数": 56,
  "去重后唯一功能数量": 32,
  "多分支共享功能数量": 18,
  "项目独有功能数量": 14,
  "Cherry-pick 关联功能数量": 6,
  "待人工确认功能数量": 4,
  "使用模型": "minimax-m3",
  "Prompt 版本": "v1"
}
```

### 4.1 字段约束

| 字段 | 类型 | 约束 |
|---|---|---|
| 仓库路径 | string | 绝对路径 |
| 分析执行时间 | string | ISO 8601 含时区 |
| 失败分支 | string[] | 无失败时为空数组 |
| 使用模型 | string | 实际调用的模型 ID |
| Prompt 版本 | string | 本次使用的 Prompt 版本号 |

## 5. 关联关系分类完整示例

### 5.1 IDENTICAL

```json
{
  "关系类型": "IDENTICAL",
  "判断依据": [
    "Commit SHA 相同：abc1234...",
    "Patch ID 相同：deadbeef..."
  ],
  "置信度": 0.99,
  "是否需要人工确认": false
}
```

### 5.2 SAME_FEATURE

```json
{
  "关系类型": "SAME_FEATURE",
  "判断依据": [
    "业务目的相同：均为 OAuth2 登录",
    "实现不同：project-a 使用 curl，project-b 使用 libcurl 封装"
  ],
  "置信度": 0.88,
  "是否需要人工确认": false
}
```

### 5.3 RELATED

```json
{
  "关系类型": "RELATED",
  "判断依据": [
    "project-b 的缓存功能依赖 project-a 的数据抽象层"
  ],
  "置信度": 0.82,
  "是否需要人工确认": false
}
```

### 5.4 INDEPENDENT

```json
{
  "关系类型": "INDEPENDENT",
  "判断依据": [
    "两个功能业务目标、接口、实现均无交集"
  ],
  "置信度": 0.95,
  "是否需要人工确认": false
}
```

### 5.5 UNCERTAIN

```json
{
  "关系类型": "UNCERTAIN",
  "判断依据": [
    "功能名称相似但代码、接口、用途无明显对应",
    "需要人工确认是否属于同一业务能力"
  ],
  "置信度": 0.4,
  "是否需要人工确认": true
}
```
