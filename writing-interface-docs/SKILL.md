# 编写对外接口文档

## 概述

读者是**其他模块的开发人员**。他们只会照文档接入，不会读你的源码。

唯一成功标准：**读者不打开任何代码就能完成对接。**

本技能不绑定任何特定技术。接口可以是消息订阅、HTTP 端点、RPC 服务、文件格式或内存调用——按实际形态选择槽位，不适用的省略，不要硬套。

## 核心配方：文档由这五部分组成

```
1. 接入信息   接入方式、寻址方式、传输语义、编码格式（按实际技术选填）
2. 输入       完整可复制示例 → 字段表 → 处理说明
3. 输出       完整可复制示例 → 空值/异常态示例 → 字段表 → 特殊语义约定
4. 处理流程   只画黑盒步骤，不出现组件名
5. 注意事项   同步/异步、无数据的表现、单位、合并规则
```

**字段表固定五列**：`字段 | 类型 | 单位 | 必填 | 说明`。类型和单位是必填槽位，不得留空或省略——对方靠它解析数据。

空值与异常示例不能省：对方必须知道"失败或查不到时收到什么"。

## 判断依据：契约还是实现

写之前对每条信息问一次：不写它，对方会出错吗？

**属于契约，要写**

- 字段名、类型、单位
- 数值符号方向（如"负值=向内"）
- 时序行为（同步/异步、顺序是否保证）
- 空值、异常、边界情况下对方收到什么
- 对方必须满足的前置条件

**属于实现，不写**

- 类名、函数名、文件名、宏名
- 数据来自哪个存储、哪张表、什么查询条件
- 内部并发模型、组件划分、所用框架或序列化库
- 生命周期、初始化顺序、排查用的日志表
- 你的实现状态：TODO、未完成、临时方案

**但要区分「内部路径」与「寻址信息」**：对方接入时绕不开的标识就是接口的一部分，必须写——网络接口的地址前缀、编译期接口的头文件路径与链接目标、库函数的公开符号名。判据是**删掉它对方还能不能接上**：接不上就写。

**边界情形的统一处理**：写对方能观察到的行为，不写你的实现状态。

对方一定会遇到的现象要写，但写成行为而非内因：

| 不写 | 改成 |
|---|---|
| "该字段由未完成的算法填充，恒为 0" | "该字段由 XX 模块填充，本版本暂未接入" |
| "用异步线程池处理，所以要等一会儿" | "响应是异步的，需按关联键匹配" |
| "数据是从 X 表按 Y 条件查出来的" | "数据由本模块自行获取，仅含当日" |

## 常见借口

| 借口 | 现实 |
|---|---|
| "这部分对接时用得上，留着有用" | 用得上的**行为**已经用契约那句话覆盖了。这一段暴露的是内因，读者用它替代不了正确实现。 |
| "写出来对方排查方便" | 排查靠日志，不靠接口文档。日志表属于维护者文档。 |
| "加一句代码位置读者更容易理解" | 读者不打开代码。指向源码等于把负担转嫁给他。 |
| "篇幅长一点更保险" | 对方要的是能抄的报文和不踩坑的约定，多余章节只会稀释重点。 |
| "这些字段有 TODO，标明免得误解" | 写成中性行为描述即可，不必暴露未完成状态。 |

## 交付前机械自检

**禁用词必须针对本模块现列**，不能沿用通用模板——通用词表在新模块里必然不匹配，恒零命中等于没有检查。

第一步，从本模块源码提取禁用词（按实际语言和框架判断，通常包括）：

- 本模块的类型名、结构体名、类名
- 内部函数名与文件名
- 用到的存储、队列、序列化库等第三方组件名
- 表名、字段名、SQL 关键字
- 内部路径、寻址前缀、配置项名

第二步，用这批词扫文档：

```bash
grep -niE '<把上一步提取的词用 | 连接>' 文档.md
```

第三步，再扫通用粗粒度模式（只能查出明显泄漏，必然有漏检）：

```bash
grep -nE '\.(c|cc|cpp|h|hpp|py|java|go|ts)\b|LIKE |SELECT |JOIN ' 文档.md
```

有命中就删掉整句——通常相邻那句里才是契约信息，提取出来改写即可。

**零命中不等于没问题**：先确认你的禁用词确实覆盖了本模块，而不是抄了一份与本模块无关的词表。

## 无依据时

某项信息在源码中无法确证时（部署形态、默认配置、外部依赖是否启用），**在文档中显式标注待确认，并主动向服务提供方提问**。不要用推测填充——对接方会把它当既成事实用，错了比留空更难排查。

## 信息不足时

字段单位、符号含义、空值语义拿不准，**主动问用户，不要猜**。单位猜错比留空危害大得多——对方会按错的口径算出一整批错数据。
